# China K12 Lesson Planning

目标不是“生成一份看起来完整的教案”，而是设计老师真正能拿去上的课堂。

## 0. 先确定教学上下文

优先级：
1. 用户本轮明确要求；
2. 用户提供的学校教材、课表、教案/PPT 模板、区校要求；
3. 匹配的已安装 Profile；
4. 国家课程标准参考；
5. 通用教学默认值。

如果 `references/profiles/` 下存在匹配 Profile，先读其中的 `PROFILE.md` 并按它要求加载最少必要 reference。不要一次读取所有 Profile。

当前仓库首个 Profile 是 `shanghai-primary-it`。它只在上海小学信息科技/人工智能场景或用户明确要求时启用，不要把上海假设套到全国教师。

没有匹配 Profile 时仍可工作：以老师提供的材料和通用教学设计原则为主，不编造地方政策、教材章节或课标编号。

## 1. 最少澄清

能从上下文推断就不要问。只有答案会明显改变课堂设计时才问，通常最多 1 个问题，例如：
- 年级完全不明且难度高度依赖年级；
- 实践课必须使用某设备/软件但环境未知；
- 主题宽到无法形成单课时目标。

课时长度优先：用户指定 > 学校材料 > Profile 明确有效要求 > 合理默认值。默认值不能冒充地方规定。

## 2. 先设计“学生经历”

优先让课堂形成：
`真实问题/现象 → 学生预测 → 体验/操作 → 观察证据 → 讨论/调试 → 提炼规律 → 正式概念 → 新情境迁移`

不要默认采用：
`定义 → 教师讲解 → 抄笔记 → 机械练习`。

不同学科可调整顺序，但必须回答：学生在课堂上到底做什么？老师如何知道他们真的懂了？

## 3. 目标与评价对齐

教学目标写成可观察行为，而不是“了解/掌握”堆叠。每个核心目标至少对应一个学习证据：作品、解释、选择理由、操作结果、短回答、Exit Ticket 等。

课标/核心素养只锚定真正相关的 1–2 项，不把政策语言堆进教案。

## 4. 新课中的分层

如果用户在“从零建课”时同时要求分层，本 Skill 直接在课内设计，不要再重复调用 differentiation：
- 基础：增加起点、样例、半成品、步骤提示或检查点；
- 提升：独立完成同一核心任务；
- 挑战：提高迁移、解释、设计、组合或开放度。

三层保持同一核心目标。学生可见名称避免能力标签。

## 5. 默认备课输出

按任务需要组织，不为凑完整而堆空话。通常覆盖：
- 学情与前置知识
- 教学目标 / 学习证据
- 重点难点
- 教学准备
- 按分钟课堂流程
- 教师关键提问
- 学生活动与任务
- 常见误解与教师应对
- 形成性理解检测 / Exit Ticket
- 分层或支架（需要时）
- 技术/材料/时间 Plan B
- 教学反思提示

“设计意图”必须解释为什么这样安排，不能反复写“培养核心素养”。

## 6. 学生语言

教师材料可以专业；学生看到的任务、练习、PPT 必须按年龄重新表达。若 Profile 提供儿童语言规则，严格使用。

## 7. 文件能力交接

如果运行环境已有 Documents / Slides / PDF 等能力：
- 本 Skill 负责教学逻辑、内容、适龄表达和质量检查；
- Documents/Slides/PDF 能力负责文件生成、编辑和版式；
- 不要求额外 bash/Node/Python Office renderer。

没有这些能力时也必须把教学内容完整交付，不因文件工具缺失而放弃教学设计。

## 8. 完成前检查

- 时间总和是否匹配？
- 学生是否真的参与而不是只听？
- 目标是否有可观察证据？
- 学生语言是否适龄？
- 是否把教学工具误写成课标强制？
- 常见错误是否来自真实推理而非臆造笑话？
- 出现设备/材料问题是否有可执行 Plan B？
